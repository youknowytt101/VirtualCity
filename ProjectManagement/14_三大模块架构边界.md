# 14 三大模块架构边界

> 本文件用于明确 WorldBuilder 当前自动化管线的官方架构口径。
> 结论：业务流程按三大模块理解和验收；核心执行入口已开始物理分层，根目录保留旧命令兼容 wrapper。

---

## 1. 总判断

WorldBuilder 当前主线应按三大块理解：

```text
数据获取 / 下载 / 缓存
    ↓
数据清洗 / 语义 / QA
    ↓
Houdini 构建 / Model QA / 审核出口
```

严格程度判断：

| 维度 | 当前状态 | 判断 |
|---|---|---|
| 流水线顺序 | `area_picker.py -> orchestration/run_pipeline.py -> acquisition/set_area.py --acquire-only -> cleaning/refine_data.py -> houdini_build/recook_new_area.py -> houdini_model_qa.py` | 严格 |
| 数据产物边界 | RawData 原始数据、`_cleaned`、`_houdini_ready`、Houdini/Reports 输出分开 | 较严格 |
| 语义契约 | `shared/vc_geo.py` 管坐标，`shared/vc_schema.py` 管 Houdini 前属性契约；根目录同名模块仅兼容旧导入 | 较专业 |
| 代码物理分层 | 核心执行入口已进入 `acquisition/`、`cleaning/`、`houdini_build/`；根目录保留 wrapper 和共享历史脚本 | 部分严格 |
| 编排职责 | `orchestration/run_pipeline.py` 已成为完整构建编排入口，`set_area.py` 保留旧入口兼容 | 已开始拆分 |

一句话：**逻辑架构已经是三大块，核心入口已经开始按三大块物理落位；剩余工作是迁移共享工具和辅助脚本。**

| 模块 | 主要入口 | 输入 | 主要产物 | 核心策略 |
|---|---|---|---|---|
| 数据获取 / 下载 / 缓存 | `acquisition/set_area.py --acquire-only`, `area_picker.py`, `download_*.py`, `_tile_cache.py` | bbox、tile_ids、area_id | `RawData/OSM/`, `RawData/DEM/`, `RawData/Overture/`, `RawData/_tiles/`, `RawData/_clip_cache/` | 缓存优先；缺失再下载；所有动作绑定 `run_id`；支持 `data-only` |

## 3. 边界规则

后续维护时按这些边界判断职责是否干净：

1. 数据获取层只负责拿到原始数据和缓存，不直接生成 Houdini 输入资产。
2. 数据清洗层负责把原始数据变成 Houdini-ready 语义数据，不直接连接 Houdini。
3. Houdini 构建层只消费 `_houdini_ready/{area_id}` 和 `active_area.json`，不重新定义数据语义。
4. `run_id` 必须贯穿 `active_area.json`、pipeline run、数据 QA、Houdini build status 和 Model QA。
5. UE5 导出导入属于审核后的出口，不是当前默认全流程测试终点。

当前允许的兼容例外：

- `Scripts/set_area.py`、`Scripts/refine_data.py`、`Scripts/_recook_new_area.py` 是兼容 wrapper，便于历史命令不立即失效。新自动化应优先调用 `orchestration/run_pipeline.py`。
- `shared/` 已承接 `vc_paths` / `vc_geo` / `vc_schema` / `vc_buildings`，根目录保留兼容 wrapper；`ue5/` 目录已预留，UE5 辅助脚本后续可继续迁移。

已经完成的边界硬化：

- `orchestration/run_pipeline.py` 成为完整构建编排入口。
- `orchestration/pipeline_state.py` 成为运行状态实现位置，根目录 `pipeline_state.py` 作为兼容 alias。
- `shared/` 成为路径、坐标、语义契约和纯建筑清洗的实现位置。
- `app/area_picker/` 成为区域选择网页应用实现位置，根目录 `area_picker.py` 作为用户级兼容入口。
- `acquisition/set_area.py --acquire-only` 成为数据获取 / 缓存入口。
- `cleaning/refine_data.py` 发布 `ready_manifest.json`，记录当前 run、schema、cache、QA 和输出文件指纹。
- `houdini_build/recook_new_area.py` 不再兜底运行 `refine_data.py`，只做 Houdini-ready preflight。
- 根目录旧入口保留为薄 wrapper，降低历史命令和网页调用迁移风险。
