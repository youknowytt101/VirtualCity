# 道路系统程序化生成优化计划 (Road System Procedural Generation Optimization Plan)

本计划旨在借鉴 Esri CityEngine 的道路系统设计思想，结合 WorldBuilder 现有的 Python & Houdini 程序化生成管线，将道路系统从现有的**“带状道路贴片”**升级为**“有拓扑、有路口、有截面规则、贴合地形”**的工业级城市道路网络。

---

## 一、 目标与评价标准

### 1.1 总体目标
完成从“简单 Sweep 扫掠条带”向“基于拓扑图（Road Graph）驱动的场景级路网系统”的架构进化。

### 1.2 评价标准
* **视觉表现**：
  * 转弯处过渡自然、圆滑，消除折线锐角。
  * 交叉路口（Junction）拥有独立的拓扑面（Patch）和圆角过渡（Corner Radius），彻底解决路口条带重叠与闪烁（Z-Fighting）问题。
  * 主干道、次干道、支路在宽度、截面、标线和附属街具上展现出明显的层级感与细节变化。
* **数据结构**：
  * 构建可查询的 `nodes / edges / blocks` 拓扑结构。
  * 产物能被后续的街区划分、建筑地块（Lots）退让、绿化带铺设以及交通流仿真直接复用。
* **工程集成**：
  * **管道内重构，两端接口保持稳定**：不破坏现有的“选区 $\rightarrow$ 数据准备与清洗 $\rightarrow$ Houdini 烘焙/Recook $\rightarrow$ UE5 导入”整体流水线。
  * 支持模块化、渐进式切换，确保每步重构可独立测试并带有回归保障。
  * 不修改既有自动化脚本入口（如 `area_picker.py`、`set_area.py`、`refine_data.py`、`_recook_new_area.py`）及导出目录/文件命名，仅在中间道路生成模块内部替换实现，以保证自动化管线与 UE5 导入逻辑的兼容性。

## 二、 优化路线与阶段划分

```
[阶段1: 2.5D拓扑清洗] ──> [阶段2: Road Graph中间层] ──> [阶段2.5: 纵坡光顺与地形回挖]
                                                                │
                                                                ▼
[阶段5: 街区与地块联动] <── [阶段4: 属性驱动截面规则] <── [阶段3: 动态裁剪路口系统]
```

### 阶段 0：锁定测试区域与基线对比 (Baseline Setup)
* **目标**：建立生成效果与性能对比的客观样本，作为回归测试的参照物。
* **行动要点**：
  1. **典型选区**：
    * **山地选区**（如 `pattaya_balihai_hill` / `pattaya_beach_hill`）：测试高差剧烈、盘山曲折路段。
    * **城区选区**（如 `pattaya_sai6_mvp`）：测试高密度、不等宽、不规则多路夹角的十字口。
  2. **存档基线**：
    * 备份当前生成的道路 Mesh（FBX/OBJ）、地形高度图及对应的原始 OSM / Overture 数据。
  3. **定点机位**：
    * 约定并记录 3-5 个关键机位的相机参数（坐标、朝向、FOV），用于后续阶段生成效果的直观对比。

### 阶段 1：2.5D 数据清洗与拓扑规范化 (Data Cleaning)
* **目标**：确保输入路网是一张严格的平面拓扑图，并防御 3D 立体交叉穿帮。
* **行动要点**：
  1. **高度层级过滤（2.5D 切割）**：
    * 优化现有的 `@/e:/VirtualCity/Scripts/refine_data.py` 和 `automation/data_processing/vc_data_cleaner.py roads`。
    * **禁止盲目的 2D 投影相交分割**：在求交点切割前，检查 OSM 标签（如 `bridge=yes`、`tunnel=yes`、`layer=*`）。
    * 只有当相交线段处于**同一高度层级**（Layer 相同，且无冲突的桥隧标识）时，才触发物理交点分割；跨线桥与地面道路保留三维空间跨越关系，互不打断。
  2. **端点吸附与微段合并（Linemerge）**：
    * 在米制投影下，对距离小于给定阈值（如 `fuse-tol=1.0m`）的孤立端点和交叉点进行强制吸附（Snap）；吸附时遵循**窄路优先吸附到宽路**的优先级规则（与 CityEngine 的 "nodes with smaller street widths always snap to segments with larger street widths" 一致）。
    * 合并共线、同方向且属性相同的碎段，消除因 OSM 采点过密带来的冗余折线。
  3. **属性标准化**：
    * 建立字典映射，将原始 `highway` 标签转换为内部等级，补全缺失的 `lanes`（车道数）、`width` 等属性：
      * `motorway` $\rightarrow$ Class: `highway_level_1`, 默认宽度: 15.0m
      * `primary` / `secondary` $\rightarrow$ Class: `highway_level_2`, 默认宽度: 10.5m
      * `residential` $\rightarrow$ Class: `highway_level_3`, 默认宽度: 6.0m
  4. **产物输出**：
    * 产生标准命名的 `RawData/OSM/area_xxx_roads_clean.geojson`。
  5. **与 CityEngine 的关键差异说明**：
    * CityEngine 的 Cleanup Graph 工具是**纯 2D 的**（官方文档明确："operates planar in the x-z plane. The y-coordinate is ignored"），桥隧处理依赖后续的 "Generate Bridges" 工具单独完成。
    * 本计划在清洗阶段即引入 2.5D 过滤（bridge/tunnel/layer），属于对 CityEngine 流程的增强方案，能在更早阶段避免 3D 误切。

### 阶段 2：引入 Road Graph 抽象中间层 (Graph Abstract)
* **目标**：在管线中正式确立“街道图”这一数据模型，告别散沙式的多段线。
* **行动要点**：
  1. **定义 Schema 规范**：
    * **Nodes (节点)**: `[id, x, z, y, degree, elevation_source, connected_edges]`（其中 `x,z` 为平面坐标，`y` 为高程）。
    * **Edges (边)**: `[id, from_node, to_node, class, lanes, width, speed_limit, oneway, geometry_coords]`
  2. **产品化拓扑提取模块**：
    * 将 `@/e:/VirtualCity/Scripts/houdini_sops/road_topology_builder.py` 中已验证的拓扑/构图算子（原 probe 版本），封装为独立且可被单测的 Python 模块/HDA，必要时仅保留 `Scripts/_archive` 中的历史代码作为参考。
    * 从 `roads_clean.geojson` 直接计算出拓扑关联的 Node 与 Edge。
  3. **兼容性接入**：
    * 在 `@/e:/VirtualCity/Scripts/_recook_new_area.py` 中重构输入端：
      `roads_clean` $\rightarrow$ 生成/读取 `road_graph` $\rightarrow$ 将几何表达降级透传给下游旧的 `_road_strips_v2`。
    * **首期目标**：视觉效果保持 100% 回归一致，确保重构不引入主流程崩溃。
  4. **权威性约定**：
    * 自本计划起，`road_graph` 作为道路几何与属性的**唯一权威数据源**；禁止新增脚本绕过 `road_graph` 直接从原始 OSM 线生成道路 Mesh，以保证所有道路都经过统一清洗与拓扑处理，并与现有自动化管线其它阶段保持一致性与可预期性。

---

### 阶段 2.5：纵坡光顺与地形适配放坡 (Vertical Grade & Cut-Fill)
* **目标**：消除盘山公路的“过山车”效应，实现平滑、物理合理的纵坡。
* **行动要点**：
  1. **一维 Laplacian 纵坡平滑**：
    * 3D 道路线贴合 DEM 地形后，在 Houdini 中沿 Curve 的流动方向执行 Laplacian 平滑滤波。
    * 限制最大纵向坡度（根据道路等级自适应：高速/主干 $\le 6\%$，支路/山地路 $\le 12\%$）。
  2. **路基开挖与填方（Cut & Fill）**：
    * 道路不只是贴在地形上。利用 3D 光顺后的路带几何，反向投影并“压平/填挖”周边的 DEM 栅格。
    * 沿路基边缘自适应计算放坡（放坡比例 1:1.5 或根据土质计算），保证路侧地形过渡平缓自然。

---

### 阶段 3：动态裁剪路口系统 (Dynamic Junction System)
* **目标**：将“路口”作为一等公民进行单独几何解算，根治重叠穿帮。
* **行动要点**：
  1. **节点自适应分类**：
    * 参照 CityEngine 的节点类型体系，按 degree + 道路等级进行细分：

      | 节点类型 | Degree | 行为 | 对应 CityEngine 类型 |
      |---|---|---|---|
      | **端点 (Cul-de-sac)** | = 1 | 生成尽端圆盘过渡 | (valence-one) |
      | **直行过渡点** | = 2 | 保留为曲线重采样控制点，不触发路口逻辑 | (valence-two) |
      | **Crossing（标准路口）** | $\ge$ 3 | 所有相交路段在节点处均被打断，生成统一路口 patch | Crossing |
      | **Junction（主路直通路口）** | $\ge$ 3 | 主路（principle street）保持几何连续不被截断，支路在路口处截断并通过 junction entry 接入 | Junction |
      | **Roundabout（环岛）** | $\ge$ 3 | 生成环形车道 + 中心岛 | Roundabout |
      | **Freeway（高速节点）** | $\ge$ 3 | 更大的 curb radius（>20），适用于 motorway/trunk | Freeway |

    * **默认策略**：采用 CityEngine "Smart" 的自动选择逻辑——当节点连接的 edge 中包含 `motorway`/`trunk` 时自动升级为 Freeway；当最大宽度 edge 与次大宽度 edge 宽度比 $\ge 1.5$ 时自动采用 Junction 模式。
  2. **Principle Street（主路）选择规则**：
    * 参照 CityEngine 规则：**宽度最大的两条 edge 自动成为主路**（"The two segments with the maximal street widths are automatically treated as major street"）。
    * Junction 模式下，主路几何在路口处不被截断，保持连续；支路在距离节点 $M_i$ 处截断，通过 junction entry 弧线接入主路边缘。
  3. **动态裁剪半径（Dynamic Clip Margin）**：
    * 设相交 Edge 集合为 $\{E_1, E_2, \dots\}$，它们对应的半宽为 $\{W_1, W_2, \dots\}$。
    * 为了确保路口的 Patch 能完整遮盖所有相交路段的端面，且不裁剪过多，每条 Edge 的裁剪距离 $M_i$ 需动态计算：
      $$M_i = \frac{W_{\text{max}}}{2 \cdot \sin(\theta)} + R_{\text{corner}}$$
      （其中 $\theta$ 是该 Edge 与相邻 Edge 夹角，$W_{\text{max}}$ 为邻路的最大宽度，$R_{\text{corner}}$ 为该路口的转弯圆角半径）。
  4. **Intersection Angle Minimum（最小交叉角弯曲）**：
    * 参照 CityEngine 的 `angleThreshold` 参数：当两条 edge 在节点处的夹角小于阈值（默认 30°）时，自动对宽度较小的支路做弯曲偏移，使其在接近路口前先向外弯曲再接入，避免产生极尖锐的路口三角形。
  5. **Resolve Conflicting Shapes（形状冲突迭代消解，架构关键点）**：
    * 参照 CityEngine 的冲突解决机制：路口 patch 生成后，检测是否存在相邻路段几何重叠（shape conflict），如某条 Edges 的长度 $L < M_{\text{from}} + M_{\text{to}}$（被两端路口完全吞没）。
    * **架构铁律**：此处的段塌缩（Collapse）与冲突消解**必须在 Python 端生成 `road_graph` 时提前计算并完成拓扑变更**，而不是仅在 Houdini 几何层做视觉裁剪。
    * **原因**：如果仅在 Houdini 几何层删除冲突路段，会导致 Python 端的拓扑图数据不一致，导致后续阶段 5 的“街区与地块分割（Blocks & Lots）”在不存在的道路上做避让分割，产生严重的对齐穿帮。
    * **消解规则**：在 Python 生成 Graph 时，计算每条 Edges 的 $M_{\text{from}}$ 和 $M_{\text{to}}$，若 $L < M_{\text{from}} + M_{\text{to}}$，则迭代合并两端节点（Merge Nodes），将极短冲突段塌缩为单一节点，并重新计算周围 Edges 拓扑关系。
  6. **Houdini Junction Patch 生成**：
    * 在节点处建立封闭边界（基于各 Edge 裁剪点与转弯圆角的控制点）。
    * 生成平整、UV 均匀的 Junction Polygon（网格化 Patch）。
    * 原始路带（Road Strip）在 $M_i$ 处截断，并与 Junction Patch 的边界顶点无缝对齐。
  7. **环岛参数**：
    * 当节点类型为 Roundabout 时，使用以下参数控制几何：
      * `innerRadius`：环岛中心岛半径（默认 5m，可根据节点连接的 edge 宽度自适应）。
      * `roundaboutStreetWidth`：环岛车道宽度（默认取连接 edge 的平均宽度）。

### 阶段 4：属性驱动截面规则与细节 (Cross-Section & Attributes Sweep)
* **目标**：用规则表（CGA 思想）统一控制**截面几何形状**，丰富车道、人行道、路缘石和排水等模型细节；当前迭代仅改进几何与拓扑，不新增/更换材质贴图，道路整体颜色保持现有统一灰色。
* **行动要点**：
  1. **截面配置文件 (Road Profile Config)**：
    * 在 `Config/` 目录下建立 `road_profiles.json`：
      ```json
      {
        "primary": {
          "lane_num": 4, "lane_width": 3.5,
          "sidewalk_l": 2.5, "sidewalk_r": 2.5,
          "curb_height": 0.15, "median_w": 1.5
        },
        "residential": {
          "lane_num": 2, "lane_width": 3.0,
          "sidewalk_l": 1.5, "sidewalk_r": 1.5,
          "curb_height": 0.12, "median_w": 0.0
        }
      }
      ```
  2. **Houdini 属性驱动 sweep (Attribute Sweep)**：
    * 在 Python 拓扑生成阶段，将 `sidewalk_l`、`lane_num` 等控制参数直接写入 Edge 几何的 Primitive Attributes。
    * 在 Houdini 中，使用统一的 **Sweep 2.0 SOP**，宽度、高度、倒角等参数直接绑定属性通道（Attribute Local Override），一节点适配全等级道路。
  3. **随机抖动与微小破坏（CGA Naturalization，几何优先）**：
    * **路缘石随机起伏（当前阶段可实现）**：使用 VEX 在路缘石（Curb）高度上叠加一个微小的噪声（如 $\pm 2\text{cm}$ 抖动），打破 CG 的绝对完美，同时仍然使用现有统一灰色材质。
    * **材质/纹理扰动（后续美术阶段）**：沿路流动方向生成二次 UV 噪声、叠加路面污渍/积水/修补纹理等效果，作为后续美术与表现力迭代时再接入的可选模块，本阶段不做强制实现。

---

### 阶段 5：街区/地块划分与建筑联动 (Blocks & Lots Coupling)
* **目标**：完成“街道-街区-地块-建筑”的闭环，让城市布局遵循交通边界。
* **行动要点**：
  1. **街区检测（Block Detection）**：
    * 利用 `road_graph` 在 2D 平面上进行封闭面检索（Planar Graph Face Construction）。
    * 排除位于界外及面积畸大（如高速公路外环外）、畸小的无效多边形，生成城区的 Block 面。
  2. **地块细分（Lot Division）与退让**：
    * 依据建筑法规，对 Block 的外轮廓向内偏移 $3\text{m}-5\text{m}$（红线退让/Setback），得到可建区域。
    * 使用 OBB（最小包围盒）或 O(N) 分割算法将 Block 细分为独立地块（Lots）。
  3. **建筑对齐驱动**：
    * 建筑的 Footprint 生成与选择不仅依赖原始 Overture 数据，还将参考其所属地块的边界：
      * 主立面自动平行于临街红线。
      * 拐角处的建筑自动裁剪或特殊化处理，形成沿街整齐的“城市界面”。

---

### 阶段 6：性能优化、LOD 与稳定性打磨 (Performance & QA)
* **目标**：在保持现有材质/贴图方案（统一灰色道路）的前提下，保证在数万个构件的宏观城市尺度下几何管线稳定、性能可控；材质 LOD 与高级表现力优化可在后续美术阶段单独立项。
* **行动要点**：
  1. **细节级别（LOD）控制**：
    * **远景（LOD2）**：关闭路口 Patch 生成，合并主次干道，简化人行道与路缘石几何（直接用平面纹理贴带）。
    * **近景（LOD0）**：全细节，包括独立的 3D 路缘石、雨水篦子、路灯及绿化。
  2. **自动数据 QA 拦截（Model QA Integration）**：
    * 扩展现有的 Model QA 清单，加入道路专项检测：
      * *悬空检测*：检测路面 Y 轴与 DTM 地形 Y 轴高差，若局部偏差 $\ge 1.5\text{m}$ 且无 `bridge=yes` 标记，则报警拦截。
      * *折叠检测*：检测 Junction Patch 几何是否出现自相交（Self-Intersection）或非流形边。
      * *坡度超标*：检测是否存在局部倾角 $\ge 15^\circ$ 的不物理悬崖路面。
