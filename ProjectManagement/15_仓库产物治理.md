# 15 仓库产物治理

> 本文件用于区分源码、配置、基准样例和运行产物，避免 RawData、区域 HIP、Reports 快照继续无边界进入 Git。

---

## 1. 总原则

VirtualCity 是 Houdini / UE5 / GIS 混合项目。仓库应优先保存：

- 可复现流程的源码、配置模板、文档和测试。
- 少量明确晋级的基准样例。
- 必须版本化的 Houdini master hip 和 UE5 项目骨架。

仓库不应默认保存：

- 每次 area_picker 运行产生的区域 RawData。
- `_downloads`、`_cleaned`、`_houdini_ready`、clip cache 等可再生成中间产物。
- 每次 Model QA / pipeline run 的运行态 JSON。
- 未晋级为基准的区域 HIP。

---

## 2. 推荐分层

| 类别 | 是否默认提交 | 位置 / 规则 |
|---|---|---|
| 源码 | 是 | `Scripts/`、`tests/` |
| 配置模板 | 是 | `Config/*.template.json`、道路规则等小型稳定配置 |
| 当前运行态 | 否 | `Config/active_area.json`、`Config/houdini_build_status.json` |
| QA / run 报告 | 否 | `Config/qa/*.json`、`Reports/model_qa/*.json`、`Reports/pipeline_runs/*.json` |
| 清洗中间产物 | 否 | `RawData/_downloads/`、`RawData/_cleaned/`、`RawData/_houdini_ready/` |
| 快速实验 RawData | 否 | `RawData/OSM/*_osm_v001.osm`、`RawData/DEM/*_dem_v001.csv`、`RawData/Overture/*_buildings_overture_v001.geojson` |
| 基准样例 | 可提交 | 放入明确命名的 fixture / baseline 目录，并在文档说明用途 |
| Houdini master hip | 是 | `Houdini/Hip/VC_master_citygen_v001.hip` |
| 区域 HIP | 否，除非基准 | `Houdini/Hip/VC_*_citygen_v001.hip` 默认忽略 |
| UE5 模板资产 | 可提交 | UE5 项目骨架和演示资产可提交；大规模生成资产另行归档 |

---

## 3. 基准样例晋级条件

快速测试区只有满足以下条件，才建议从运行产物晋级为基准样例：

1. `Config/houdini_build_status.json` 同一区域为 `completed`。
2. `Reports/model_qa/latest.json` 同一区域无 `fail`。
3. 若 Model QA 为 `warn`，必须有同一 `run_id` 的人工审核记录。
4. 在 `ProjectManagement/02_当前状态与下一步.md` 或区域记录中说明该样例用途。
5. 文件体量可接受，或已明确使用 Git LFS / 外部 artifact 存储。

---

## 4. 当前历史状态

仓库里已有一批历史 RawData、区域 HIP 和 UE5 资产快照。它们暂时视为历史实验快照，不在本轮批量删除。

后续清理建议：

- 先列出仍有价值的基准样区。
- 把基准样区移动到清晰的 baseline / fixtures 策略下。
- 对非基准历史快照执行一次单独 cleanup commit。
- cleanup commit 不应混入功能修改。
